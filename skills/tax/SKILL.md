# 세무 검토 (tax)

한국 세법 질문을 받아 **두 개의 MCP**로 법령·판례·예규·조세조약을 검색하고,
근거 기반 검토의견을 작성한다.

| MCP | 무엇 | 언제 쓰나 |
|---|---|---|
| **korea-tax-law** (`mcp__korea-tax-law__*`) | 국세·지방세 60개 법령 조문, 판례·심판례 15만, 국세청·법제처·행안부 해석례 14.8만, 조세조약 조문 3천 — **본문까지 그래프 DB에 적재** | 세법 안의 일이면 여기부터. 조문 본문 키워드 검색·해석례 본문·조약 조문은 여기서만 된다 |
| **korean-law** (`mcp__korean-law__*`) | 법제처 국가법령정보 실시간 API. 전체 법령·자치법규·행정규칙·별표·18개 도메인 결정례 | 세법 밖, 별표·서식, 시행예정 개정, 특정 시점 시행본, 인용 검증 |

한쪽이 다른 쪽의 상위 호환이 아니다. **용도가 갈린다** — §2와
`references/source-search.md` §2의 라우팅 표를 따른다.

사용자 입력: $ARGUMENTS

## 0. 준비

- **경로 확인**: 이 SKILL.md와 같은 폴더의 `references/`에 단계별 지침이 있다.
  아래에서 "references/…"는 항상 이 스킬 폴더 기준 **절대경로로 풀어서** 사용한다
  (서브에이전트에 넘길 때 특히).
- **MCP 확인**: 두 서버의 도구가 보이는지 확인한다
  (`mcp__korea-tax-law__search_articles`, `mcp__korean-law__search_law`).
  - 둘 다 없으면 검색을 진행하지 말고 MCP 설정이 필요하다고 안내한다 (README 참조).
  - **korea-tax-law만 있으면** 그대로 진행하되, 별표·시행예정·비세법이 필요한
    대목에서 "해당 정보는 확인하지 못했다"고 답변에 명시한다.
  - **korean-law만 있으면** 진행하되, 국세청 해석례 본문과 조세조약 조문은 링크
    안내까지만 가능하다는 점을 답변에 명시한다.
  - **자체 지식만으로 세법 답변을 만들지 않는다.**

## 1. 모드 결정

| 모드 | 언제 | 무엇 |
|---|---|---|
| **easy** (기본) | 단순 조회·일반 설명·빠른 확인 | 검색 + 답변 작성. 1~2분 |
| **hard** | 사용자가 명시(`hard`, "정밀 검토", "딥하게")했거나, 복합 쟁점·고액 리스크·해석 대립·과거 과세기간 판단이 걸린 질문 | 4단계 전체 파이프라인 (분석 → 검색 → 검증 → 답변). 5분 이상 |

- 인자 첫 단어가 `easy`/`hard`면 그 모드로 확정하고 나머지를 질문으로 본다.
- 지정이 없으면 easy로 시작하되, 질문이 hard 기준에 해당하면 **easy로 답한 뒤
  말미에** "쟁점이 복합적이니 `hard` 모드 정밀 검토를 권합니다"를 붙인다.

## 2. easy 모드

메인 컨텍스트에서 직접 수행한다. 별도 분석·검증 단계 없이 **검색 → 답변** 두 걸음.

1. **검색**: 질문에서 적용 조문·쟁점 키워드를 뽑아 아래 라우팅대로 검색한다.

   | 찾는 것 | 도구 |
   |---|---|
   | 세법 조문 (키워드만 앎) | `korea-tax-law: search_articles` → `get_article` |
   | 세법 조문 (법령명·조번호 앎) | `korea-tax-law: get_article` — 위임 하위법령까지 함께 온다 |
   | 조문 개정 연혁 | `korea-tax-law: get_article_history` |
   | 판례·조세심판원 결정례 | `korea-tax-law: search_cases` |
   | 국세청·법제처·행안부 해석례 | `korea-tax-law: search_interpretations` |
   | 조세조약 | `korea-tax-law: search_treaties` / `get_treaty_article` / `list_treaties` |
   | 별표·서식 (기준금액·세율표) | `korean-law: get_annexes` |
   | 시행예정 개정 확인 | `korean-law: search_law` |
   | 특정 시점 시행 본문 | `korean-law: legal_analysis` mode=`applicable_law` |
   | 비세법·조례·행정규칙 | `korean-law: search_law` → `get_law_text` |
   | 판례 전문 (사건번호 앎) | `korean-law: get_decision_text` domain=`precedent` |

   - **국세청 해석례 본문은 korea-tax-law에만 있다.** korean-law의
     `search_decisions(domain='nts')`는 목록·링크만 주고 본문 조회를 지원하지 않는다.
   - **조세조약 조문 본문도 korea-tax-law에만 있다.** korean-law는 조약 메타데이터와
     링크까지다.
   - 검색 확장 순서: 직접 적용 조문 → 위임 시행령 → (불명확할 때만) 예규 → (판단
     기준이 판례로 형성된 쟁점만) 판례. 앞에서 충분하면 뒤는 검색하지 않는다.
   - 서로 독립인 검색은 병렬 호출.
2. **답변**: `references/answer-generation.md`를 Read하고 그 지침대로 작성한다.
   - easy 모드는 검증 단계가 없으므로 지침 §4의 easy-mode 주의 의무(단서·예외·
     적용제외 함께 제시)를 반드시 지킨다.

## 3. hard 모드

원본 tax-ai-agent 파이프라인의 4단계를 **단계별 서브에이전트**로 실행한다.
오케스트레이터(메인 컨텍스트)는 아래 실행 규칙만 따르고, 법률 판단을 직접 하지 않는다.

```
사용자 질문
  → [1] Query Analysis (서브에이전트)
      ├─ clarification_needed.required = true
      │    → 재질문 내용을 사용자에게 그대로 전달하고 종료 (검색 시작 금지)
      └─ false
           → [2] Source Search (서브에이전트)
           → [3] FactCheck (서브에이전트)  ※ lookup_only=true면 생략
               ├─ supplement_search 있음 → [2]를 해당 키워드로만 1회 재실행 → [3] 재실행
               └─ 없음
           → [4] Answer Generation (서브에이전트)
  → 답변을 그대로 사용자에게 전달
```

**실행 규칙** (원본 execution-manager 규약):
1. 오케스트레이터는 세법상 쟁점이나 검색 대상을 자체 판단하지 않는다 — 각 단계
   산출물을 **가공 없이** 다음 단계에 전달만 한다.
2. Query Analysis가 재질문이 필요하다고 하면 검색을 시작하지 않는다. 사용자가
   답하면 원래 질문과 합쳐 [1]부터 다시 실행한다 (두 번째 라운드는 재질문 없이
   본 검토로 진행).
3. 보충 검색은 FactCheck의 `supplement_search`에 명시된 키워드만, **최대 1회**.
4. `lookup_only=true`(단순 조회형)면 [3]을 건너뛰고, [4]에 "검증 단계가 생략되었으니
   단서·예외 규정을 반드시 함께 제시하라"는 주의를 덧붙인다.

**서브에이전트 호출 방법** — 각 단계는 general-purpose 에이전트로 실행한다.
프롬프트 형식 (경로는 절대경로로):

- **[1] Query Analysis**:
  > `<references 절대경로>/query-analysis.md`를 Read하고 그 지침을 정확히 따라
  > 아래 세무 질문을 분석하라. 출력은 지침 §3의 JSON만 반환한다.
  > 사용자 질문: <질문 원문 그대로 — 요약·재작성 금지>
  > (후속 라운드면: 직전 문답 맥락도 함께 전달)
- **[2] Source Search**:
  > `<references 절대경로>/source-search.md`를 Read하고 그 지침을 정확히 따라
  > korea-tax-law·korean-law 두 MCP 도구로 근거를 검색하라. 지침 §2의 라우팅
  > 표를 반드시 지킨다. 출력은 지침 §4의 JSON만 반환한다.
  > Query Analysis 결과: <JSON 전문>
- **[3] FactCheck**:
  > `<references 절대경로>/fact-check.md`를 Read하고 그 지침을 정확히 따라
  > 근거를 검증하라. 출력은 지침 §4의 JSON만 반환한다.
  > Query Analysis 결과: <JSON 전문> / Source Search 결과: <JSON 전문>
- **[4] Answer Generation**:
  > `<references 절대경로>/answer-generation.md`를 Read하고 그 지침을 정확히 따라
  > 최종 답변을 작성하라. 출력은 사용자에게 보여줄 답변 본문만 반환한다.
  > 사용자 질문: <원문> / Source Search 결과: <JSON> / FactCheck 결과: <JSON 또는 "생략됨(사유)">

## 4. 답변 전달

파이프라인(또는 easy 모드)이 만든 답변을 **그대로** 사용자에게 전달한다.

- 요약하지 않는다. 다듬지 않는다. 문단을 재배열하지 않는다.
- 근거를 추가하거나 결론을 보태지 않는다. 스스로 아는 세법 지식으로 거들지 않는다.
- 답변이 이상하거나 근거가 빈약해 보이면, 고치지 말고 그 사실을 사용자에게 말한다.
- 말미에 항상 붙인다: *"본 스킬의 답변은 AI가 공개 법령정보를 검색해 작성한 참고
  의견이며, 세무대리인의 검토를 대체하지 않습니다. 실제 신고·처분 대응 전 반드시
  회계사 또는 세무사와 상담하세요. 답변의 정확성·완전성은 보장되지 않으며, 이를
  근거로 한 의사결정의 책임은 사용자에게 있습니다."*

## 5. 공통 답변 원칙

- 모든 법적 판단에 조문번호·판례번호·문서번호 인용 필수
- **검색으로 확인한 근거만 인용** — 자체 지식의 조문번호를 검색 없이 쓰지 않는다
- 확정적 단언 금지 → 조건부 표현 사용
- 반대 근거 병기 의무
- 사실관계 미확인 시 "확인 필요" 명시 (단 방향성 있는 결론과 함께)

## 6. 실패 시

| 증상 | 대응 |
|---|---|
| 두 MCP 도구가 모두 안 보임 | MCP 설정 안내 (README 참조). 자체 지식으로 답하지 않는다 |
| 한쪽 MCP만 보임 | §0 규칙대로 진행하고, 못 채운 정보를 답변에 명시 |
| korea-tax-law 호출 실패 | 세법 조문·판례는 korean-law로 대체. 해석례 본문·조약 조문은 대체 불가 — 그 한계를 답변에 명시 |
| MCP 호출 연속 실패 | 2~3회 재시도 후 사용자에게 서버 상태를 알리고 중단 |
| 검색 0건 | 키워드 일반화 1회 재시도 → 그래도 없으면 답변에 그 한계를 명시 |

실패를 자체 지식으로 메우지 않는다. 실패는 실패로 보고한다.
